# BBB設定・レインボー・中央エリアの統合

後続の調整は [最新の修正報告](RAINBOW_AREA_LIFE.md) を参照。以下は統合時点の記録。

## 実装内容

- ホームの「最大ライフ」で1〜4を選択。初期3、保存キーは `bbb.maxHP`。不正値は3へ戻す。ソロは試合開始時に全員へ適用し、回復・復活もその上限を使う。試合中のホーム設定変更は進行中の試合に反映しない。
- オンラインはサーバーのルーム設定で最大ライフを管理。作成時にホストの保存値を送信し、その後はロビーのホストだけが変更可能。ゲストの保存値は送信しない。変更時は準備完了を解除し、再戦・ホスト交代でもルーム設定を維持。スナップショットの最大ライフで表示も更新する。
- チュートリアルは練習HP4と既存の保護処理を維持する。
- モデル・描画の初期画質を軽量に変更。保存された標準・高画質は維持する。描画設定の保存キーは `bbb.renderQuality`、モデル画質は従来の `bbb.modelQuality`。描画設定が未保存なら保存済みモデル画質を引き継ぐ。専用魚モデルも同じモデル生成経路に画質パラメータを渡す。
- 水たまりの通常回復は毎秒10→20ポイント。フレーム時間に比例し、100で停止。チュートリアルの回復案内・達成判定も更新。
- レインボーで入水すると一度だけ50ポイント追加回復。水中でレインボーが成立した場合にも未発動なら加算。退出で発動済み状態を解除し、再入水時にレインボー条件を満たせば再発動する。既存の「入水でコンボリセット」は維持し、その前にボーナスを処理する。
- レインボー中の消費倍率0.5を共通のジャンプ開始処理で一度だけ適用。A/Dは1→0.5、Spaceは2→1ポイント。通常回復には適用しない。
- 既存のレインボーA/D成功50BP、速度1.5倍を維持。Spaceの周期と従来の基本BP計算は維持する。
- ノーマル中央は半径4.2、厨房中央は横4.8・縦4.3の楕円を設定。着地位置が内側なら通常の獲得BPを一度だけ2倍にする。レインボーA/Dは100BP。黄色の境界と床面の「BP ×2」を全画質で表示する。水たまり・設備の当たり判定は変更しない。
- 2秒以上ほぼ移動できない壁への押し付けでは着地BPを止め、コンボをリセット。衝突による補正、予定移動量、実際の移動量を利用する。短い接触は許可し、壁から0.08m以上移動すると解除する。
- CPUは中央目標の選択率72%、25コンボ以降の回復判断を水分25%へ調整。20コンボ以降は90%の確率で次の入力までの待ちを短縮し、コンボを維持しやすくする。低水分時の回復、被弾時の水たまり脱出、コックへの対応は維持。接近する包丁には短い横回避を追加する。
- CPUの近距離判定は5m。反応待ち0.22秒、照準追従2.1rad/秒、近さに応じた追加照準誤差を設定。予測射撃1/3・現在位置射撃2/3と基本の攻撃間隔は維持。ソロとオンラインは同じAIを使用する。

## 検証

- ゲーム側189件、サーバー側20件の自動テスト成功。
- 設定の保存・不正値、全ライフ値での死亡・復活・回復上限、ホスト権限、試合中の変更拒否、再戦時の維持を確認。
- 毎秒20ポイントの回復を30/60/120Hzで確認。50ポイント追加回復の重複防止・上限・再入水、レインボー消費半減と解除、着地位置に応じた2倍加点、壁押し付け停止と復帰を確認。
- CPUの近距離照準誤差が遠距離より大きく、継続時の発射回数はほぼ同じであることを固定条件のテストで確認。接近包丁への回避と自分の包丁の除外も確認。
- ソロ・サーバーの共通シミュレーションで、最大ライフ・BP・レインボー・消費量が一致することを確認。
- チュートリアルの実操作シミュレーション、FPS練習、終了後の破棄、魚・イカの各画質でのアニメーション・メッシュ安定性の既存テストも成功。
- Vite本番ビルド・GitHub Pages参照検査成功。検証環境のパス制限を避けるため既存の検証用preserveSymlinks指定を使用。公開設定は変更していない。既存の大きなバンドルに関する警告は残る。
- ブラウザUIテストを追加したが、Edgeが起動時に終了し実行できなかった。実画面の配置・高画質イカの点滅・GPU負荷は未確認。
- Colyseus実通信テストも実行したが、子サーバーの起動表示後のHTTP接続確認に失敗し、複数接続テストへ進めなかった。実機2〜4人接続・本番WSS・実通信での再戦は未確認。サーバーの純粋な進行管理テストでの再戦は成功している。
