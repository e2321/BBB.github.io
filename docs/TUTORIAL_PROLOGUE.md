# BBB体験チュートリアル

既存の専用魚モデル、カメラ切り替え、描画ループ、ステージ素材を再利用する。通常BBB・オンラインの進行管理や通信処理は変更していない。

## 進行と操作

- 導入：4つの短い文章を約4.4秒で表示。A/D入力ですぐ練習へ進める。
- 1：A/Dを交互に入力し、実際の着地で4コンボ。BPとコンボを画面に表示する。
- 2：練習用に水分を45%へ調整したことを表示し、水たまりで実際に15ポイント回復する。補助による水分変更は達成量に含めない。
- 3：水たまり内で左クリックし、攻撃不可を体験。外に出て実際に包丁を投げると次へ進む。
- 4：TPSで練習CPUを狙って左クリック、既存のVキーでFPSへ切り替え、FPSでCPUに1回命中、VでTPSへ戻す。切り替えと命中の順序を必須とする。切り替え前の包丁は命中課題へ流用しない。攻撃間隔は本編と共通。
- 5：Spaceジャンプを実行し、実際の着地で成功。水分消費2%を案内する。
- 6：A/Dで8コンボと、この挑戦中に100BPを獲得すればクリア。CPUの撃破は不要。SpaceによるBPはこの課題の達成量には含めない。

FPSは狙いやすくするための選択肢として紹介し、攻撃後はビタンビタンが主役であることを繰り返す。FPSでは既存処理により自分のモデルを非表示にする。

## 練習の補助

説明再表示、練習位置への復帰、練習CPUの静止、いつでもBBBへ進めるスキップを用意する。攻撃練習のCPUは時間がかかると静止し、命中後はHPを補充する。最終課題だけ4.5秒間隔で控えめに攻撃する。死亡後も達成済みの段階を維持する。水分が15%を下回った場合は20%へ補給し、その理由を表示する。制限時間によるやり直しはない。

通常ルールと同じA/D消費1%、Space消費2%、回復毎秒20%、練習用最大HP4を使用する。以前のチュートリアルだけの水中攻撃許可を取り除いた。通常・オンラインのライフ設定（初期3）とは独立して練習用HP4を維持する。旧コースや素材は再利用できる形で残している。

## 検証結果

- ゲーム側の自動テスト173件、サーバー側20件が成功。
- 実際のシミュレーション入力で、水分回復、水中攻撃拒否、TPS→FPS→TPS、命中、Space着地、最終8コンボ・100BPを検証。撃破数0で完了。
- 各段階に7秒の待ち時間を加えた自動操作は約58.4秒、待ち時間なしは約17.6秒。実際の初心者の所要時間を示す数値ではない。
- Three.jsの実際のカメラ・表示処理を、描画用の簡易モデルとDOM代替で検証。FPS時の自分のモデル非表示、TPS復帰、生成済みモデルの継続利用、終了時のイベント・モデル破棄を確認。
- Vite本番ビルドとGitHub Pages向け参照検査が成功。環境固有のパス権限問題を避けるため、検証時のみpreserveSymlinksを指定。既存Vite設定・公開ワークフローは維持。
- ブラウザテストも更新したが、Edgeが起動時に終了し3件とも実行できなかった。実画面での読みやすさ、点滅、GPU負荷、初心者による操作、実機2台のオンライン対戦は未確認。
- GitHubへのPush・デプロイは実行していない。
