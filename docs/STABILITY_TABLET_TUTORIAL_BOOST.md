# 終了フリーズ・タブレット・虹色説明・ブースト着地BP

## 終了時フリーズの原因

実ブラウザの通常ビタン操作で、次の例外を再現した。

```text
TypeError: Illegal invocation
at BPNotifications.arm
```

前回のBP通知管理でネイティブの `setTimeout` / `clearTimeout` をそのままオブジェクトのプロパティへ保存し、`this.cancel(...)` 等で呼んでいた。ブラウザでは不正な呼び出し元として拒否されるため、通知の生成・削除時に例外となった。終了処理の先頭も通知削除だったので、結果画面を表示する前に停止する経路があった。Nodeの注入タイマーだけのテストでは検出できなかった。

呼び出しは `globalThis.setTimeout(...)` / `globalThis.clearTimeout(...)` を使うラッパーへ修正した。タイマーの呼び出し元を検証する回帰テストと、実ブラウザのBP発生・終了テストを追加した。

併せて確認できた別の問題として、記録保存のリスナーの例外が結果表示より先に伝播しうる構造だった。以下の対策を追加した。

- 終了状態を READY → FINISHING → RESULTS で管理し、終了処理は一度だけ実行。
- 結果画面の表示を記録・効果音より先に実行。保存・通知・ポインタ解除・効果音の失敗は個別に記録し、残りの終了処理を継続。
- 記録保存リスナーを個別に保護し、他のリスナーや画面遷移を止めない。
- 終了後は通常の物理・モデル更新を行わず、不要なBP通知とそのタイマーを消去。
- 描画中の例外を記録して単一の描画ループを維持。`renderDiagnostics()` の errors / lastError で確認可能。
- 再戦・ホーム復帰・再開始で終了状態をリセット。ページの強制リロードは使用しない。

オンラインはロビー維持に必要な接続・pingを残す。終了だけを理由にルームを破棄しない。HP0時も既存の死亡・刺身・リスポーンを維持し、無限リスポーンを脱落制へ変更していない。

## タブレットの原因と修正

タッチUIの初期判定が主ポインターの `pointer:coarse` に依存していた。トラックパッド等で主ポインターがfineとなるタブレットでは、タッチ可能でもPC扱いになりうる状態だった。

- 主ポインターだけでなく `any-pointer:coarse` と `navigator.maxTouchPoints` を利用。
- タッチ可能端末はマウス入力を受けてもタッチUIを不必要に解除しない。通常のタッチ非対応PCでは従来どおり。
- 保存済みボタンを画面内・セーフエリア内に補正。重なりがある場合は表示配置を調整し、回転後も操作できる配置にする。保存した元の相対座標は勝手に上書きしない。
- 配置編集のドラッグ・サイズ変更・保存・キャンセル・初期化を維持。
- 描画サイズとカメラのアスペクト比は、canvasの実表示領域を基準に更新。DPR上限・画素数上限・サイズ更新の集約は維持。
- 既存のメニュー縦スクロール、横画面案内、ワンタップ・視点スワイプ・攻撃・視点切り替え・自動射出を維持。

## チュートリアルと虹色

ユーザー確認に従い、最終課題は **30コンボ＋100BP以上**。50コンボを必須課題にはしていない。30コンボ到達までに通常計算で595BPを得るが、課題のBP下限100は維持した。

追加した説明：

- 「50コンボで虹色状態に突入、1回50 BPのチャンス！」
- 虹色のアニメーション約1.5倍、水分消費0.6ポイント。
- 虹色中に水たまりへ入ると＋50ポイント、30%→80%、上限100%。
- 最終課題は30コンボでよいこと。
- PCでは「ブースト中のビタン着地で追加+10 BP！」も案内する。

水分消費はユーザー確認どおり **0.6を維持**。添付の「半減（0.5）」へ戻していない。水たまりへの入場時の50回復、重複防止、上限100は既存実装とテストを維持した。水たまりでは既存どおり回復後にコンボが終了するため、説明もそのルールに合わせた。

添付の指定に従い、虹色1.5倍は描画アニメーションだけに適用する。物理の滞空時間・水平推進へ虹色倍率を掛けていた旧処理を分離した。通常時の物理・移動は変更していない。魚・イカ・CPU・ソロ・オンラインで共通。

自動操作テストでは、反応待ちなしで約27秒、各段階7秒の待ちを含む場合は約62秒で30コンボ課題まで完了した。実際の初心者による所要時間の測定ではない。

## ブースト着地の＋10 BP

ユーザー確認どおり、単独ジャンプやSpaceキーのジャンプは復活させていない。スマホ・タブレットにもジャンプボタンは追加していない。

- ブーストが有効な状態で実際に始まったA/Dビタンの、得点可能な着地に固定＋10BP。
- 押しただけ、同じキー連打、未着地、水中着地、死亡、水分不足の減点着地、壁押し付け稼ぎでは追加しない。
- 離陸時のブースト適用を記録するため、滞空中に効果時間が切れても実際のブーストジャンプの着地には付く。
- 一度の着地で一度だけ。追加分はコンボ数・コンボ倍率を変更しない。通常のA/D着地自体の1コンボは維持。
- 通常の着地BPとは別。虹色なら50＋10＝60BP。＋10へコンボ倍率は適用しない。
- 共通の `grantBP` を使い、獲得BP統計・合計HUD・結果へ反映。
- 追加通知は既存の上限4個・850ms削除・重複防止のBP通知を再利用。
- 定数 `BOOST_LANDING_BP=10`。オンラインは共通シミュレーション内でサーバーが判定。成功の自己申告イベントは受理しない。
