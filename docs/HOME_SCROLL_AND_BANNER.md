# ホーム画面の上下スクロールとスマホ告知

## 原因と変更

ホームの `#overlay.arcade-home` は固定された画面サイズ内のグリッドだが、`align-content:center` で縦中央に配置していた。タイトル・説明・ロビー等の合計高さが画面を超えると、グリッドの開始位置がスクロール領域より上になり、スクロール位置0でも上側の内容へ到達できなくなる構造だった。小さい幅では別のCSSが上寄せしていたが、広い画面や一部のスマホ横画面では中央寄せが残っていた。

併せて、チュートリアルボタンのHTML `autofocus` と、サブ画面を閉じる際の通常の `focus()` が意図しないスクロールを起こしうる状態だった。

- グリッドを上端基準・内容の高さの行へ変更した。
- `height:100dvh`（`100vh`フォールバック）と縦スクロール・横はみ出し抑制・`min-width:0` をホーム自身に適用した。
- 小さい横画面では列を柔軟に縮め、600px以下なら1列にして横にはみ出す固定最小幅を解消した。
- 実績・カスタマイズ・統計・設定パネルも、画面内の独立した縦スクロール領域とした。
- スクロール領域に `touch-action:pan-y`、慣性スクロール、スクロール連鎖の抑制を設定した。
- 初期フォーカスは既存のチュートリアルへ `preventScroll:true` で移す。初期選択は維持する。
- ホームへ新しく戻る際は1回だけ最上部へ戻す。サブ画面を開いた際のホーム位置を保存し、閉じた際はスクロールさせないフォーカス復帰と位置復元を行う。
- スクロール位置を毎フレーム強制する処理は追加していない。画面回転時は動的ビューポートと通常のブラウザの範囲補正を利用する。

`body` の `overflow:hidden` はゲーム画面用に維持した。ホームはbodyではなく固定コンテナ自身がスクロールする。`touch-action:none` とタッチの `preventDefault()` はゲームcanvasや操作ボタン・配置編集に限定され、ホーム上のスワイプをキャンセルする全体リスナーは見つからなかった。ゲームの視点操作、配置編集、回転案内の処理には変更を加えていない。

## バナー

タイトルの直下、対戦メニューより上に通常のコンテンツとして追加した。

- `📱 スマホプレイ対応！！`
- `PCでもスマホでもビタンビタン！`

黄色〜オレンジの角丸・影・太字で既存の青系アーケード背景と合わせた。小さい横画面では文字・余白を縮小する。固定配置、ボタン操作、追加の描画ループ、外部フォント読み込み、点滅アニメーションは使用していない。

## 変更ファイル

- `home.css`：スクロール範囲、グリッド、サブ画面、小画面、バナー。
- `home-ui.js`：初期フォーカスとスクロール位置の保存・復元。
- `game.js`：ホームへ戻った際の位置リセット。
- `index.html`：バナーとHTML autofocusの削除。
- `tests/home-ui.test.js`：初期位置、フォーカス、サブ画面復帰位置、不要な再リセットがないこと。
- `tests/home-scroll.browser.js`：実際のHTML/CSSを使う5サイズのレイアウト回帰テストを追加。
- 本書。

## 検証結果

- Node自動テスト279件すべて成功。ゲームルール・既存メニューの回帰テストを含む。
- Vite本番ビルド、GitHub Pagesの相対パス検査は成功。既存の大きなチャンク警告は残る。
- ブラウザ回帰テストは実行を試みたが、Edgeが起動直後に終了し、5ケースとも検証本体を実行できなかった。画面の問題を検出した失敗ではなく、ブラウザ起動段階の失敗。
- PCのホイール/トラックパッド、スマホの実スワイプ、iOS Safari/Android Chrome、回転案内、バナーの実表示と折り返しは未確認。

ブラウザが起動できる環境では、次のコマンドでモデルやサーバー接続なしにレイアウトテストを実行できる。

```powershell
npx playwright test tests/home-scroll.browser.js --workers=1
```

その後、実際のゲームでホームを上下へ操作し、実績等を開閉、友達ロビーや接続エラーの長文表示、ゲームからホームへの復帰、端末回転を確認する。公開設定・サーバー・得点計算は変更していない。Push・デプロイも実施していない。
