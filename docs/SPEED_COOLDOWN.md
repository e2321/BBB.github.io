# BBBのビタン速度・投擲間隔調整

## 変更した定数

- `NORMAL_FLOP_SPEED = 0.85`：BBBの通常A/D周期・移動・表示へ適用。
- `RAINBOW_FLOP_SPEED = 1.25`：従来の1.5から変更。通常の0.85に一度だけ掛け、合成速度は1.0625。
- `PLAYER_KNIFE_COOLDOWN_MULTIPLIER = 0.8`：基準 `BATTLE.fireInterval = 0.6` 秒から、プレイヤーのみ0.48秒へ短縮。
- `knifeFireInterval(player)`：CPUは基準0.6秒のまま。CPU AI側の追加待ち時間・攻撃頻度の計算は変更していない。

## 挙動

通常A/Dは周期を従来の1/0.85に伸ばし、水平速度は0.85倍にする。レインボーは新しい通常速度の1.25倍。ジャンプの高さは周期に合わせて初速・重力を計算し、同じ水分での最高到達高度を維持する。1回の水平移動距離はほぼ維持し、移動速度とアニメーションを一致させる。

加速なしの周期は通常約0.588235秒、レインボー約0.470588秒。60Hz物理更新では着地まで36／29ステップ。交互入力による従来の加速もそのまま使う。水分・コンボ・通常BP・レインボー50／70BPは変更しない。

入力直後の離陸は維持。BBBでは空中で受け付けた次のA/D入力が長くなった周期の途中で期限切れにならないよう保持する。同じキーの連打では加速や無制限の連続ジャンプが起きない。速度は離陸ごとに設定し、レインボー移行時の重複倍率や、解除後の追加待機を防ぐ。

魚の既存アニメーションには共通の周期・速度値を渡す。イカの腕の遅れ・しなりの補間も0.85の速度を受け付けるようにした。モデル・メッシュは変更していない。Spaceの周期・高さ・水平慣性、チュートリアルのA/D周期と操作は維持する。

ナイフの待ち時間はソロ・サーバー共通の発射処理で決定する。オンラインの役割はサーバー側で管理し、クライアントから待ち時間を偽装できない。飛行速度14、飛行時間3秒、ダメージ、弾のプール数・命中判定は変更していない。

## テスト結果

- ゲーム側200件成功（並列数1で実行）、サーバー側20件成功。
- 魚・イカ、プレイヤー・CPU、ノーマル・厨房で、周期・水平速度・高さ・消費量・BP・加算1回を確認。
- レインボー終了直後の通常速度への復帰、倍率の重複防止、空中の交互入力保持、同じキーの連打防止を確認。
- プレイヤー0.48秒／CPU0.6秒の直前は拒否、境界では発射可能。同時刻での連打も拒否。
- サーバー入力処理でも0.48秒の検証と、待ち時間を含む不正な入力の拒否を確認。
- 共通シミュレーションとサーバーの周期・初速・重力・水分が一致し、既存のリモート描画履歴へ合成速度が引き継がれることを確認。
- イカの低・標準・高画質の安定性テストに0.85／1.0625を追加し、メッシュ交換・座標異常・カリング範囲逸脱がないことを確認。
- Vite本番ビルドとGitHub Pages参照検査成功。検証用preserveSymlinks指定を使用し、公開設定は維持。既存の大きなバンドルに関する警告は残る。
- 実際のブラウザ画面での動きの自然さ・点滅、複数PCのオンライン通信・遅延は未確認。自動テストの状態・数値検証と区別している。
