# 開発者・通常のガチャ共有と排出動画（2026-10-17）

## 変更内容

- 開発者のガチャタブを通常モードと同じ `bbb.collection.v1` の残高・所持品へ接続。
- 「共有コイン +500」または数値指定で付与。共有ガチャで100／900コインを消費し、獲得したキャラクター・武器・水しぶき・演出を通常の所持リストへ保存。
- 通常モードでの消費後、開発者メニューを開き直すと保存済み残高を読み直して表示。終了・再読み込みでも保持。
- 「共有アイテムを装備」から通常の装備画面へ移動できます。未所持装備の禁止を維持。
- シミュレーション、全解放などのTEST用ツール、TEST試合、RP変更ツールは引き続き独立。共有コインとガチャ獲得品をTEST初期化で削除しません。

## 認証と二重付与の防止

通常残高は元からブラウザ保存で、オンラインサーバー管理の口座・アカウントではありません。その構成を維持しています。同じブラウザ・同じゲームURL内でモード間共有され、別端末や異なるOrigin間の同期はしません。

- 付与・開発者共有ガチャを行う前に、既存の管理者セッションを使ってサーバーで権限を確認。
- 新しい `sharedCoins`／`sharedDraw` 操作は、未認証・期限切れを拒否。金額、整数、回数、ガチャ、操作IDを検証し、既存の管理操作レート制限も適用。
- 同じID・同じ内容は同じ受領情報を返し、同じIDの内容変更は409で拒否。
- ブラウザの通常保存にも受領IDを残し、再認証・再送・再読み込みで同じコインや抽選を二度処理しません。
- 共有付与と通常／共有ガチャは同じWeb Locks名を利用し、保存直前に残高を読み直します。Web Locks非対応環境でも同一画面の処理中ガードを維持。
- 抽選の消費・獲得品・抽選IDを1回の保存にまとめています。
- 保存失敗や通信失敗時は操作IDのみを保留保存。再認証後に「保留操作を再試行」で続行可能。パスワード・管理トークンはこの保存へ入れません。
- 残高不足の抽選は保留操作でコイン付与を妨げないよう処理。
- ローカル保存は従来どおりユーザーが編集できるため、オンラインの所持証明として新たに信用する変更はしていません。

## 既存データ

通常残高・所持品の保存キーとversion3形式は維持し、既存データを初期化しません。

旧開発者残高は別のlocalStorageキーではなく、サーバーの管理セッション内だけにあった一時的なTESTデータです。通常残高へ単純加算する移行は行いません。既に終了・失効・再起動で消えた旧TEST残高は復元できません。新しい認証済みの共有付与を使用してください。

`bbb.developerCollection.pending.v1` は未完了操作のIDと値だけを保持し、別残高ではありません。

## 動画

- 通常排出：`public/assets/gacha/videos/normal.mp4`
- 既存のレア枠であるキャラクターを含む排出：`public/assets/gacha/videos/rare.mp4`
- 10連はキャラクターが1個でも含まれればrareを使用。
- 実際に見つかった元ファイルは開発フォルダーの `public/assets/gacha/normal.mp4.mp4` と `rare.mp4.mp4` でした。元を残し、指定のvideosフォルダーへ正しい名前でコピー。
- 2本とも約10.006秒、H.264のMP4。normal約5.54MB、rare約5.39MB。
- ViteのBASE_URLから動画URLを生成し、GitHub Pagesのサブパスにも対応。
- 画面幅・高さ全体の動画領域を使用し、object-fit:containで映像を切らずに最大表示。スマホもインライン再生。
- 自動再生の互換性のため動画はミュート。既存ガチャ効果音は従来の音設定を使用します。
- 動画終了後は実物モデル／エフェクトを中央の大きなプレビューに表示し、その下に結果カード一覧。閉じるまで保持。
- 抽選結果と所持品を動画より先に保存。スキップ・エラー・30秒の読み込み待ち切れ・3分の再生停止時も保存結果を表示し、再抽選しません。
- 自動再生が拒否された場合は再生ボタンを表示。スキップも常時利用可能。
- 閉じる／結果への移行で動画を停止し、ソース・イベント・タイマーを解放。新しい描画ループは追加しません。
- 以前の固定7／9／10秒のCSS演出に代わり、実際の動画終了に合わせて結果へ進みます。

## 検証

- フロント：357件成功。普段の開発フォルダーでも357件成功。開発フォルダーに欠けていた既存の焼き魚画像と古いテスト1件を本体に揃えました（ゲームルールの変更なし）。
- サーバー：54件成功。
- 追加テスト：500付与→通常消費→開発者へ戻る→保存再読込、4カテゴリの所持と装備、同じ操作の再送／再認証、保存失敗と復帰、未認証・不正金額・異なる再送内容の拒否、RP・勝利数・対戦履歴の分離、残高不足後の再操作。
- 動画テスト：通常／レアの分岐、Pages URL、MP4ヘッダーとH.264情報、終了・失敗・待機タイムアウト・スキップ・自動再生拒否・後始末。
- Vite本番ビルド・Pages相対パス検査成功。動画2本がdistにコピーされ、元と同じ内容であることをハッシュ確認。
- 実際のPC／スマホブラウザでのログイン・動画デコード・音・表示サイズ・本番通信は未確認。前回のブラウザ確認では、この環境のEdgeがページ表示前に終了していました。自動テストのメディアイベント検証と、実ブラウザでの再生確認は区別しています。

## 公開時

GitHubへのpush、Pages公開、Render再デプロイは実行していません。

**共有付与を公開版で利用するには、フロントだけでなくRenderのサーバーも今回のコードへ更新する必要があります。** 古いサーバーのままなら付与は拒否し、更新が必要なメッセージを表示します。認証パスワードの環境変数・Pagesワークフロー・通常のオンライン対戦通信仕様は変更していません。
