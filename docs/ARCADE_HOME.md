# アーケードホーム・実績・カスタマイズ実装記録

## ホーム

青・水色・黄色・オレンジのアーケード風に変更。タイトル「捌かれるな！！」、サブタイトル「BITAN BITAN BATTLE」。クイックマッチ／ソロ／友達／チュートリアル／実績／カスタマイズ／戦績・統計／設定を配置した。

チュートリアルが起動時・ホーム復帰時の初期選択。クイックマッチは別の大きな主要ボタン。マウス、タップ、Tab/Enter、モードの矢印/Home/End移動に対応。ダイアログは閉じる/Escapeとフォーカス復帰を備える。チュートリアルの完了画面にホーム復帰ボタンも追加した。ライフ1〜4（初期3）・画質軽量・スマホ操作設定は既存の要素を再利用している。

魚/イカの既存モデルを低画質で再利用し、ホームとカスタマイズの3Dプレビューを表示。プレビュー専用の既存rendererを共有し、ゲームのrendererは使わない。アプリの既存RAFから最大12Hzで描画し、別のRAFは追加していない。通常のカード画像はキャッシュを維持。ゲーム中・別パネル閲覧中・非表示タブではライブプレビューを描かない。OSのprefers-reduced-motionと設定の軽減を利用でき、モデル生成エラーは5秒待ってから再試行する。

## 統計の集計規則

- 総プレイ回数＝完走＋開始済みの途中終了。カウントダウンだけで退出した場合は含めない。
- 自己ベスト：最大コンボ、完走時の最終BP、1試合の獲得BP、完走時のビタン回数・レインボー回数、最長連続生存秒。
- 累計：ビタン発進、獲得BP、得点対象のコンボ着地、レインボー到達、勝利、敗北、試合時間、実際の包丁射出、ダメージ成立した包丁命中。
- 獲得BPは正の通常得点・奇襲・キル奪取の合計。減点は獲得累計から引かない。最終BPは減点後の順位確定時の値。BP系実績は獲得BPで判定する。
- 平均コンボ＝完走した試合ごとの最大コンボの平均。最大コンボ、平均最大コンボ、累計コンボ着地は別指標。
- 勝率・平均BP・平均順位は完走だけを分母にする。0試合はすべて0。同点1位は既存ルールの同時優勝。
- 魚/イカのプレイ回数、人間2人以上/人間1人＋CPUの完走を分離。人間数は試合開始時の人数で固定。
- 途中終了は活動量と有効なコンボ/生存/獲得BP記録を保存するが、勝敗・平均・最終BPの自己ベストには含めない。切断したまま終了した枠はサーバーで勝敗集計の対象外にする。短時間で復帰して完走した場合はサーバーのスロット記録を使用する。
- ソロ/オンラインを別保存し、画面で総合も表示。チュートリアルは全指標から除外。
- オンラインはサーバーが積算したカウンター・確定結果を利用し、移動予測は記録を変更しない。終了時は本人だけへ結果を送信し、再接続時も再送できる。

試合ID（オンラインはルーム固有乱数＋ラウンド＋参加枠）、ビュー側の記録済みフラグ、直近512件の保存済みIDで重複を防ぐ。結果画面に今回のBP・最大コンボ・ビタン・順位・虹到達、新規実績、NEW RECORDを表示する。

## 保存形式

localStorageの新規キー bbb.progression.v1 にJSONを保存する。version:1、solo/online（各累計とbest）、unlocks（実績ID→ISO日時）、equipped（title、fish/squid別color/effect）、seen（試合ID）、proof（署名済みオンライン記録）、reduceMotionを持つ。既存の操作・画質・ライフ保存キーは触らない。

破損JSON、未知バージョン、不正数値、未知ID、保存拒否を安全に処理。実績解除・試合終了/途中終了・装備/軽減変更・新しい検証トークン受信時だけ保存し、毎フレームは書かない。初期化は2段階確認で、この新規データだけを消す。別ブラウザ/端末へ自動同期はしない。

## オンラインの検証

ローカル実績は端末内の記録であり、サーバー保証ではない。オンラインでの装備は、オンライン完走によってサーバーが計算した累計から改めて許可する。ソロだけで解除した装備は、オンラインで同条件を満たすまでオンライン表示では通常装備になる。画面にその違いを案内する。

サーバーはHMAC署名トークンを発行し、次の接続時に署名・統計値・装備IDを検証する。改ざんしたlocalStorageや自己申告の勝利数は受け付けない。署名トークンは本人へだけ送信し、他人に配るlobby/snapshotへ入れない。公開同期は装備ID・称号IDなど最低限の表示情報だけ。新しいアカウントやDBは導入していないため、トークンはアカウントの本人証明や端末間同期サービスではない。

### Renderに必要な設定

継続してオンライン装備を保持するには、Renderの環境変数 BBB_PROFILE_SECRET に32文字以上の十分にランダムな秘密値を設定する。Render管理画面のEnvironment → Add Environment Variableから登録する。秘密値は通常の端末で `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` などで生成できる。実値をGitHubやVITE_変数へ入れない。server/.env.exampleには空欄と説明のみ追加した。

未設定でもサーバーは動くが、秘密鍵がプロセスごとに変わるため再起動でオンラインの検証記録が失効する。ローカル実績と統計は残るが、オンライン装備の再検証はやり直しになる。接続画面でもこの状態を案内する。秘密値を変えた場合も古い署名は失効する。

友達ルームはユーザーの追加回答に基づき2桁数字へ変更した。00〜99を文字列として扱い、予約済みとの重複を防ぐ。既存の最大4人、ロビー維持・再戦・ホスト移譲、クイック専用ルームの分離は維持する。クイックの内部識別用コードは6文字のままで、手入力は不要。
