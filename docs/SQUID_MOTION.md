# イカ専用のビタンビタン改善

## 変更ファイル

- squid-motion.js（追加）：胴体・ヒレ・腕の関節、時間に基づくしなり、遅延、着地の潰れ、履歴とオンライン予測時刻の補正。
- seafood-model.js：既存のイカ形状をスキンメッシュとして生成し、新アニメーションを接続。旧来の単純な全体回転と根元だけの腕振りを置換。
- battle-view.js：既存の入力種類・開始時刻・周期を描画用ポーズに渡す。オンラインのローカルイカには最大50msの表示用時刻補間を適用する。魚の処理は追加フィールドを使用しない。
- tests/squid-motion.test.js / tests/squid-motion.browser.js（追加）：変形・遅延・接地・Space・品質差・時刻補正・描画の検証。

魚モデル、fish-model.js、fish-quality.js、fish-contact.js、ゲームの物理・BP・水分・HP・当たり判定、サーバーと通信プロトコルは変更していない。グローバル描画ループと点滅対策のrender-runtime.jsも変更していない。

## 動き

A/Dでは軽い逆向きのためから胴体をしならせ、腕の根元→先端の順に追従する。直近4入力を保持して連続入力を滑らかにつなぐ。8本の腕と2本の触腕を区別し、触腕の遅れ・振幅を少し大きくした。腕ごと・関節ごとに位相をずらす。

着地状態の変化を一度だけ検出し、小さな圧縮と横への広がり、腕の揺れ戻りを短く減衰させる。最大約6%程度の圧縮に抑え、極端な伸縮は行わない。側面ヒレは胴体と方向転換にわずかに遅れて追従する。

Space自体はA/Dの胴体振りを追加せず、既存の位置・高度に追従する。モデルの追加上下バウンドはない。接地時は変形後の表面から描画位置だけを補正する。

## 軽量化とオンライン

共通のqualityパラメータを維持。関節数は軽量25、標準48、高画質72。メッシュ数は従来の14個で、頂点数・形状・頂点バッファはアニメーション中に変更しない。関節行列による変形を使用し、メッシュの生成・破棄はフレーム内では行わない。画面外の描画省略も、動きの範囲を含む境界球で維持する。

腕ごとの状態は送信しない。既存のキー・開始時刻・周期・接地・位置情報からクライアント側で再生する。同じ状態の繰り返しや、ローカル予測とサーバー開始時刻の小さな差を重複した動作として数えない。モデル破棄時は各個体のスケルトンと材質を解放する。

## 確認結果

- 新規7テスト：画質ごとの関節数、8腕＋2触腕、メッシュ・頂点バッファ不変、骨ウェイト、胴体の実変形、腕先の遅れ、全頂点による床接触、Spaceの位置・入力データ不変、同じオンライン時系列の一致、パケット重複と予測補正の統合を確認。
- 全自動テスト：ゲーム152件＋サーバー20件成功。
- 4体同時のCPU側更新を300回測定：軽量0.289ms、標準0.385ms、高画質0.473ms／フレーム。Node.js環境の簡易測定であり、GPU描画・ブラウザー・実機FPSの結果ではない。
- Vite本番ビルド・Pages出力チェック成功。既存のパス権限問題を避けるため、検証時のみpreserveSymlinksを指定。リポジトリの公開設定は変更なし。既存のチャンクサイズ警告あり。
- ブラウザーテストはEdgeが起動時に終了し、ゲーム表示まで到達できなかった。実画面での自然さ、実測FPS、オンライン複数PCの見た目、全画面点滅が再発しないことは未確認。

公開へのPush・デプロイは行っていない。今回はクライアントの描画変更のみで、サーバー更新は不要。
