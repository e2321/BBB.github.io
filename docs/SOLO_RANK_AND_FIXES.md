# ガチャ画像・認証修正とソロランク戦（2026-10-17）

## 調査した原因

- 公開用リポジトリ BBB/public/assets/gacha/ にはREADMEのみでした。開発用フォルダ側の public/assets/gacha/ に4枚のユーザー作成画像があり、公開用へ取り込まれていませんでした。
- 元ファイル名は ocean.webp、deepsea.webp、crustocean.webp.jpg、funny.webp.jpg。先頭2枚は拡張子と異なりPNG形式で、甲殻類には名前の綴り違いと二重拡張子がありました。
- 従来の種類別ガチャボタンにはバナー画像を読み込む処理がありませんでした。個別排出アイテム用PNGと種類別バナーは別用途です。
- 認証クライアントは `globalThis.fetch` を `this.fetcher` に保持し、`this.fetcher(...)` として呼んでいました。その呼び出しではreceiverがDeveloperClientになり、ブラウザのfetchのreceiver要件に違反します。
- 初期作業状態はクリーン、開始HEADは `62a0d7b597d4be939cc7058972c4c048b50eaa39`。既存のゲーム・所持・公開設定を巻き戻していません。

## ガチャ画像の修正

4つの種類別バナーを追加。読み込み成功時のみ画像を表示し、未配置・失敗時はガチャ名入りの色付きバナーを表示します。
読み込み失敗URLはコンソールへ同一URLにつき一度出力。壊れた画像アイコンを隠し、一覧・抽選は継続します。
ファイル名・拡張子・大文字小文字は次のとおりです。

- 海のなかまたち：public/assets/gacha/ocean.png
- 深海：public/assets/gacha/deepsea.png
- 甲殻類：public/assets/gacha/crustacean.jpg
- おもしろ海洋生物：public/assets/gacha/funny.jpg

`joinAssetURL` と `import.meta.env.BASE_URL` で結合し、先頭・末尾スラッシュを正規化します。
開発時の例は `/assets/gacha/ocean.png`。
現在の相対パスビルドでは `./assets/gacha/ocean.png` を使い、公開URLでの実際の解決先は
`https://e2321.github.io/BBB.github.io/assets/gacha/ocean.png` です。他の3枚も同じ位置で解決します。
ユーザー作成の4枚を内容を変更せずコピーし、実際のPNG/JPEG形式と拡張子を一致させました。元ファイルは変更・削除していません。
画像は生成していません。WebPへ差し替える場合は実データもWebPにし、gacha-config.js の banner を更新してください。
公開画面へ反映するには今回の画像ファイルも含めたビルド・公開が必要です。
画像を差し替えて再公開した後はページを再読み込みしてください。古い表示が残る場合は強制再読み込みで確認します。
既存の個別アイテム画像（character-starfish.pngなど）の命名と代替アイコンは維持します。

## 認証修正

fetchを `globalThis` にbindし、ログイン・管理操作・ログアウト・キャンセル後の遅延トークン破棄に共通適用しました。
receiverの一致を要求するfetchモックを使い、旧方式ではエラーになる呼び方を再現してテストしています。

パスワードはフロントへ埋め込まず、Renderの `BBB_ADMIN_PASSWORD` を使うサーバー一致判定を維持。
指定された秘密値をRenderの環境変数へ設定してください。本書・公開コードへ秘密値は記載しません。
成功→15分の管理セッション→即メニュー表示、管理操作ごとの権限確認、試行制限、ログアウト失効を維持します。
追加承認・メール・アカウントは不要です。
パスワード不一致、接続失敗、95秒の起動待ちタイムアウト、404のAPI不足、5xxの内部エラー、不正なログイン応答を分けて表示します。
通信待ち中はRender起動待ちの案内とキャンセルが使えます。Render APIキーや定期pingは追加していません。
Render上の環境変数と実際の認証結果は未確認です。

## ソロランク戦

ソロ対戦の「ソロ形式」で通常ソロ／ランク戦を選択します。
通常ソロの自由設定は維持。ランク戦だけ厨房・プレイヤー1人＋CPU3体・コック2体・最大HP3・90秒へ固定。
ホームのライフ・コック設定の値は書き換えず、試合開始時に別の固定値を適用します。
オンラインやチュートリアルにはランク設定を適用しません。

初期RP0、下限0。順位のRPは1位+30／2位+10／3位−10／4位−20、途中退出−20。
同BPは従来の競技順位（例：1位・1位・3位・4位）を使い、同順位は同じRPと報酬。
表示順・プレイヤーIDで同点の報酬を変えません。

ランク境界・難易度・試合コイン：

- ブロンズ：0〜99 RP、難易度0.8、完走20＋1位10。
- シルバー：100〜249 RP、0.9、完走25＋1位15。
- ゴールド：250〜449 RP、1.0、完走30＋1位20。
- プラチナ：450〜699 RP、1.15、完走40＋1位25。
- ダイヤモンド：700〜999 RP、1.3、完走50＋1位35。
- マスター：1000 RP以上、1.45、完走60＋1位40。

アイコンと色、現在RP、次ランクまで、最高ランク、難易度、報酬を開始前に表示。
結果は順位・BP・RP増減・更新後RP・試合コイン・昇格／降格の短いアニメーションを表示します。
報酬とCPU難易度は開始時のランクを固定し、試合後の昇格でその試合の報酬を再計算しません。
同じ結果IDの再処理ではRP・参加数・コインを増やしません。
通常の試合コイン付与はランク戦では無効にして二重付与を防止。
実績解除の15コインは既存の実績ID別請求を使い、通常の活動した試合では試合報酬と別に一度だけ付与します。

途中退出・リロード・タブ終了では途中退出扱いにします。
開始時に未完了IDを保存し、次回起動でも未完了があれば一度だけ減点。
退出時は試合コインを付与しません。残高不足・負RPにはしません。

## 放置対策と保存

有効なプレイは、10秒区間のうち4区間以上で実際のビタン入力が成立し、得点対象の着地が6回以上あり、
4m以上の実移動＋2つ以上の2m区画を通る、または実命中があることを条件にします。
実際の物理ステップ・着地・移動・命中を使い、無効な連打・自動射出だけでは活動と判定しません。
放置扱いでは試合コインもその結果による実績コインも付与しません。RPは確定順位に従います。
初心者の低BP・少ないキルだけを理由には排除しませんが、実機での判定感覚は未検証です。

保存は既存統計と別の `bbb.soloRank.v1`。
現在RP・最高ランク・参加数・完走数・1位回数・累計獲得BP・最高コンボ・最後の結果ID・重複防止履歴・未完了IDを保存。
コイン保存に失敗した場合も、確定済みRPを再加算せず、次回起動時に同じ報酬IDで再配達します。
通常の所持・統計データは既存キーで維持します。

**ランクは端末内のローカル記録です。改ざん防止された公式競争には、サーバー上での試合検証・RP保存・署名済み所有／称号証明が別途必要です。**
複数タブで同時にソロランク戦を行う用途は検証していません。

## CPU調整

ランク専用フラグがある場合のみ、難易度を判断間隔・索敵距離・照準誤差・攻撃判断間隔・近距離反応・
回避の選択率・回復に向かう水分閾値・コンボ継続率・停滞時の再計画間隔へ変換します。近すぎる敵から間合いを取り直す距離もランク別に変え、回復・コック回避を優先したまま既存の経路探索に渡します。
係数を移動速度・加速・BP・HP・水分・射程・ダメージへ掛けません。
近距離反応は最低0.16秒、攻撃判断間隔は既存のCPU武器クールダウン以上を守ります。
既存の経路探索・水たまり回避・首位への控えめな狙い・予測射撃比率を維持。
通常ソロとオンラインのCPUにはこの係数を設定しません。
難易度プロファイルは再利用し、毎フレームの追加メッシュや描画ループは作りません。

## 称号

装備中称号を既存プロフィールと選択中キャラクター名の下に大きく太字で表示。
スマホは18px、PCは最大26px。長い文字列は折り返します。
対戦中の頭上称号は18px→最大25pxへ拡大し、長い場合は幅に合わせて縮小。
既存の遮蔽・距離・FPSでの自分の表示抑制を維持。
結果の名前欄に装備称号を併記し、優勝行を強調。

ブロンズビタン／シルバービタン／ゴールドビタン／プラチナビタン／ダイヤモンドビタン／マスタービタンを追加。
最高到達ランクの実績で解除し、降格しても失いません。ブロンズはランク戦初完走で解除します。
既存の累計ビタン称号「ビタンマスター」と区別するため、ランク最上位は「マスタービタン」にしました。

オンラインの既存称号は従来のサーバー検証と同期で表示します。
新しいソロランク由来の称号にはサーバーで確認できるRP証明がないため、正式オンラインでは未許可として通常表示へ戻ります。
この制限をクライアント自己申告で迂回していません。
