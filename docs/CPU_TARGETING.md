# CPUの攻撃対象選択

## 変更内容

- 既存の「人間プレイヤー0が1位なら確率で対象を差し替えて追跡」を削除。BP最多の魚に、人間・CPUの区別なく控えめな攻撃対象ボーナスを適用する。同点1位も同条件。全員0BPなら順位ボーナスなし。
- 自分、死亡中、HP0、観戦枠、無敵中は対象外。従来の射程25m以内かつ障害物に遮られない対象から選ぶ。
- 優先度は距離を主軸に、1位補正、現在の対象への維持補正、他CPUの集中数を組み合わせる。遠い1位や遮蔽物の向こうの1位は優先しない。
- 対象を1.2〜1.8秒維持。死亡・射程外・射線喪失では次のAI更新で再選択。維持中も明らかに有利な相手（優先度1.6倍以上）が現れれば変更できる。維持時間後も12%以上の改善がない限り切り替えない。
- 対象判断を0.35〜0.65秒ごとに予約し、既存0.2秒間隔のAI更新で確認する。乱数はシミュレーションの既存シードを使用。CPU全員の同時変更を避け、通常は対象スコアを毎フレーム計算しない。
- 移動は水分回復・危険回避・刺身・ジャンプブースト・通常のBP稼ぎの既存優先順位を保つ。ランキングによる直接追跡は行わない。
- 射撃頻度0.85、予測射撃1/3、現在位置への射撃2/3、近距離エイム弱体化、コンボ継続・レインボー判断は維持。復活時は対象と維持タイマーを初期化する。
- オフラインとオンラインのサーバーが共有するBotControllerを変更。ルーム、再戦、通信形式の変更なし。中央エリアは追加していない。

## 調整定数

battle-rules.js の BOT_TARGET_RULES：
- leaderBonus: 0.12（1位優先度+12%）
- currentBonus: 0.08（現在対象の優先度+8%）
- focusPenalty: 0.28（既に狙っているCPU数に応じて分母を増加）
- holdMin: 1.2 / holdJitter: 0.6秒
- decisionMin: 0.35 / decisionJitter: 0.3秒
- switchRatio: 1.12 / urgentSwitchRatio: 1.6
- range: 25m / distanceOffset: 2m

battle-ai.js、battle-rules.js、battle-simulation.js、tests/bot-targeting.test.js、README.md、本書。親の開発用ミラーへも反映。

## 検証結果

ゲーム自動テスト211件が全成功。その後追加したCPU3匹の継続分散テストも成功（固有テスト計212件、対象選択テストは9件）。サーバーテスト20件全成功。Vite本番ビルドとPagesアセット参照検査成功。既存の環境用ビルド補助スクリプトを使用。大きいバンドルの警告は残る。

同距離の人間/CPU1位優先、近距離の別対象優先、壁・射程外・死亡・観戦・無敵除外、集中回避、ランキング変動時の維持、明確に有利な対象への変更、判断時刻の分散、水分管理と通常移動の維持、サーバーとオフラインの共通選択を確認。両ステージの固定配置で、8秒間の判断中にCPU3匹が1位へ集中し続けないことも確認した。唯一攻撃可能な相手が1位の場合など、集中を一律禁止する制限は設けていない。

実ブラウザでのプレイ感・複数PCによる本番オンライン対戦は未確認。GitHub Push・Pages公開・Renderデプロイは未実施。オンライン反映にはサーバー側の更新が必要。
