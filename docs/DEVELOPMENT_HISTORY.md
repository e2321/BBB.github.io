﻿# 捌かれるな！！ — プロローグ＆ビタンポイント対戦

既存ゲームを使い、最終の追加指示に合わせた **2モード** に統合しました。FPS/TPS対戦がメインです。サバイバルのステージ・増援・称号・ランキング処理は削除しています。変更前は `backups/v3-before-three-modes/` に保全済みです。

## 起動

Node.js 20.19以上、または22.12以上で：

```powershell
npm.cmd install
npm.cmd run dev
```

**http://127.0.0.1:5173/** を開いてください。モデル読み込み後、FPS/TPS対戦またはプロローグを選択してSTART。依存パッケージがすでに入っていればインストールは不要です。ブラウザーにはBlenderやCodexは不要です。

```powershell
npm.cmd run build
npm.cmd run preview
```

配布用 `dist/` を生成し、通常 http://127.0.0.1:4173/ でプレビューできます。今回の対戦は完全にクライアント内で動き、WebSocket・通信サーバー・ログイン・ルームはありません。依存取得後はインターネット不要です。配布版は任意の静的HTTPサーバーで動作し、Node.jsをゲームの通信サーバーとして使用しません。HTMLを直接 `file://` で開く構成ではありません。

## FPS/TPS対戦

追加調整：CPUは攻撃ごとに予測照準1/3・現在位置照準2/3をランダム選択します。発射後の包丁は直進し、追尾しません。移動AI・弾速・攻撃間隔・ダメージは維持しています。

対戦のA/Dビタンは初速度5.6・重力22.4とし、以前の初速度2.8・重力11.2に比べて実際の跳躍高度を約2倍にしました。初回の実測は約0.345m→0.689m、滞空時間0.5秒・距離約1.97m。水分消費は最新指定の1回2ポイントです。プロローグの物理・姿勢・アニメーションには変更を加えていません。対戦のA/D処理を修正しており、Spaceのアクションは追加・変更していません。

あなた1匹＋BOT3匹で、30m × 30mのアリーナを90秒間プレイします。勝敗は **ビタンビタンポイント** で決まり、同点は同順位・同時優勝です。キル数では順位を決めません。

| 操作 | 効果 |
| --- | --- |
| A / Dを交互に押す | 前方へ跳ねる。空中の入力も受け付け、次の着地後のジャンプへつなぐ |
| 交互入力を速くする | 加速・跳ねる頻度が増加。厳密なタイミング合わせは不要 |
| マウス | 左右で進行方向、上下で照準。上下±60度。魚の胴体を照準に合わせて立てない |
| 左クリック | 包丁を投げる。毎0.6秒、20m/s、弾数無制限 |
| V | FPS / TPS切り替え |
| 水たまり内でA / D | ジャンプせず、地面を滑って出る。押し続けても誘導可能 |
| Esc | 一時停止 / 再開。タイトルへ戻る操作も可能 |
| F2 | FPS・CPU処理時間・描画数・音声数の診断表示 |

同じキーの連打・押しっぱなしでは加速しません。入力を止めると加速は徐々に失われます。上限は通常の約2.1倍の頻度（最大約4.2ビタン/秒）。水分不足による弱体化は加速と併用します。

### 着地・得点・水分

- 得点は **実際の空中→接地の判定** で1回だけ加算。1着地＝10 pt。
- ジャンプ開始時に水分を2消費。初期100、上限100、下限0。
- 投げる・外で立っているだけでは水分を消費しません。
- 水分低下で同じ魚のアニメーションを弱くし、跳ぶ高さ・距離・勢いも減少。0でも移動できます。
- 中央に3つの水たまり。中では毎秒5回復し、ビタン・得点はできません。
- 水の中はA / Dで滑って動け、マウスで方向を変えられます。強制ジャンプ・暴走はありません。
- 境界には7cmの判定余裕を設け、微小な位置変化で入退場と回復を繰り返さないようにしています。
- BOTも同じ入力・水分・得点ルール。水分低下で補給を優先し、回復後は水場を出て得点へ戻ります。

`battle-rules.js` の `FLOP_RULES` で着地点数、水分消費、吸収率、回復速度、弱体化曲線、加速上限などを調整できます。

### 戦闘・死亡

HPは3。自動回復なし、3回命中で死亡。高速な包丁は移動区間と魚のカプセル形状で当たり判定し、壁や自分をすり抜けてダメージを与えません。命中した魚だけ0.15秒間白く点滅します。

撃破すると、相手の現在ポイントの10%（整数切り捨て）を吸収し、相手から同量を減算します。1死亡につき1回のみ、自滅・攻撃者不明では吸収なし。ポイントが負になることもありません。

死んだ魚は約0.3秒で縮んで消え、同じ場所に白い皿と刺身7切れが現れます。プレイヤーとBOTで共通。皿は3.5秒で消え、死亡から5秒で復活。残りポイントを維持し、HP3・水分100へ戻ります。復活後1秒間は無敵で点滅し、攻撃すると無敵が解除されます。死亡中の移動・攻撃・得点は無効です。

画面右上の4匹の順位表はリアルタイムに更新します。順位データを王冠にも共用し、同点1位の生きている魚すべてに表示。自分の王冠はTPSで確認できます。試合終了後の最終順位表から同じオフラインロビーへ戻り、再戦できます。

### 魚・視点

既存のGLBを共有して4匹へ複製し、全長1.5mへ拡大。青・赤・緑・黄の控えめな色味で区別します。全員の性能・HP・判定は同じです。

横倒しの姿勢、口を開いてC字に曲がる尾打ち、空中のしなりと着地は **プロローグの既存アニメーションを再利用**。対戦だけの姿勢を立てる回転は加えません。TPSは後方約3m、壁に応じて距離を調整。FPSは自分のモデルを隠します。カメラの上下動は抑え、両視点とも中央の照準の到達点へ包丁を向けます。

## プロローグ（チュートリアル）

旧脱出モードを改名しました。まな板で包丁を構えられる導入、食材・食器の足場、厨房から最後の排水溝への脱出を維持しています。

- 後半のコンロ区間を削除し、炎の区間は前半の1か所（3バーナー）に。
- 後半の料理人・ワゴン・柵を削除し、必須の死んだふりは前半の1回に。
- 削除した区間は通れる調理台としてつなぎ、最後のシンクまで到達可能です。
- 食器8個、5チェックポイント、水分回復、疑い度、広い奇襲成功時間、原因別ゲームオーバー、Retryとタイトルへ戻る操作を維持。
- 魚の姿勢・ジャンプ速度・推進・2段ジャンプ・リズム操作は変更していません。
- コックは既存骨格と顔・服を保った頂点クラスタリングで72,276→44,886三角形へ軽量化。追跡・投擲・拾い上げ・気絶を維持しています。

A / Dで跳ね、空中でもう一度で2段ジャンプ。止まると死んだふり。「今だ！」で奇襲し、ワゴンを突破します。炎への接触は即死、高温は水分減少。死因は捕獲・包丁・炎・乾燥・落下を区別し、既存の料理写真と演出を維持しました。

## 効果音

適切な録音素材は既存プロジェクトにありませんでした。外部素材は追加せず、Web Audioでオリジナルの音源バッファを事前生成して再利用します。

着地音は低い体の衝撃、帯域を整えた湿った水音、短い水滴の共鳴を重ねています。通常・軽い・強い・高速・乾燥の音を分け、毎回の音程・音量・わずかな時刻を変化。実際の着地イベントに同期し、乾燥時は弱い「ペチッ」になります。

水場へ入る水しぶき、補給中の小さな水音、包丁の風切り・金属音・湿った命中、刺身化、ポイント吸収、1位撃破、復活、首位獲得、残り10秒、勝敗発表の音を追加しました。着地音を優先し、補助音は小さくしています。他の魚は距離減衰と左右の定位、自分の音は直接聞き取りやすく再生します。

AudioContextはユーザーのSTART操作で1つだけ作り、各モードで共用。最大8音、優先順位とコンプレッサーで重なりを制限します。音源は毎フレーム生成しません。`wet-audio.js` の `replaceSample(name,url)` で将来のWAV/MP3を読み込んで差し替えできます。生成方法・権利は [ASSETS.md](ASSETS.md)。

## 検証

```powershell
npm.cmd test
npm.cmd run test:browser
npm.cmd run build
```

ブラウザーテストは、別ターミナルで開発サーバーを起動して実行します。インストール済みMicrosoft Edgeをヘッドレス・ソフトウェアWebGLで使用。

ロジックテストは、加速、実着地と重複防止、水分−2、無消費の投擲、水場での回復と滑り退出、境界の安定性、BOTの補給と得点、10%吸収、5秒復活、壁・高速包丁、順位・同時優勝、90秒のBOT対戦を検証します。プロローグは実操作の経路で5CP、食器8個、奇襲1回、最後の排水溝まで到達。初期の待ち時間0～2秒の4パターンでもクリアしました（経路を知る自動操作で約66～71秒）。

ブラウザーでは実モデル・口・横倒し・入力・FPS/TPS・包丁・音声再生イベント・順位・王冠・刺身化・再戦・モード終了・プロローグクリア・死亡画面を確認します。個別判定の検査と高速な90秒試合の検査には開発フックを使用します。試合エンジンの時計・AI・物理は通常どおり進め、90秒間を人間が実時間で遊んだテストとは区別します。

配布確認：プレビューを `npm.cmd run preview -- --port 4174` で起動後、`node tests/production-smoke.mjs`。`window.__game` は開発版だけに存在します。

## 残る制約・未確認事項

- Ryzen 5 5625U・8GB・内蔵GPUの実機FPSと操作感は未測定です。描画負荷の計測・上限・再利用を実装していますが、対象PCで快適に動くと断言はしません。
- 魚は既存の約44MBのGLB・4Kテクスチャを維持しており、初回読み込みは大きめです。新しいGLBの取得やBlender実行は行っていません。
- 音は独自の合成音です。波形・音源再利用・実際の再生イベント・定位設定を検査しますが、録音した本物の魚のFoleyではありません。スピーカー・ヘッドホンでの聴感調整は別途必要です。
- 移動・当たり判定はゲーム用の近似です。全員同じカプセルで判定し、曲がる魚の各頂点へ精密な判定は行いません。
- 対戦バランスの実ユーザーテスト、スマートフォンでの対戦操作、オンライン対戦は今回の確認対象外です。プロローグの従来のタッチ操作は保持しています。

## 最終確認結果

- `npm.cmd test`：39件すべて成功。元の魚・コックGLBがバックアップと同じSHA-256であることも確認しました。追加修正では実跳躍の約2倍、CPU照準の比率、空中での包丁回避も検査しています。
- Edge / Playwright：6件成功。削減後のプロローグ、交互入力と音の同期、乾燥・水場と退出、FPS/TPS、包丁、刺身化・5秒復活、順位・同点王冠、90秒終了、再戦、画像失敗への対応を検証。跳躍頂点で実座標Y=約0.969m（床上の基準Y=0.28m）・モデル位置一致・TPS内の表示も確認。
- OfflineAudioContext：実際にステレオPCMを生成し、左側の音源の左/右RMSは約0.0137/0.00223、8音同時再生のピークは約0.745（1未満）でした。
- `npm.cmd run build`：成功。723kB程度のJSにサイズ警告は出ますが、配布ファイルを生成しています。
- 配布用プレビュー：プロローグ・対戦のモデル読み込み、START、入力、HUD、FPS切り替えと攻撃を確認。ページ例外・HTTPエラーなし。配布版に開発フックがないことを確認しました。
- 画像は `tests/screenshots/v4-*.png` に保存。

ヘッドレス環境ではAudioContextはrunningになってもリアルタイム時計が0のままでした。そのため再生要求・波形・定位は確認しましたが、スピーカーからの実音と聴感は未確認です。音声シナリオの個別試験では残った音を停止してから次の条件を検査し、実際の音声処理はOfflineAudioContextで別に確認しています。音が無音・一時停止の環境でも、モード終了や音の差し替え時には音声ノードを即座に切り離します。
