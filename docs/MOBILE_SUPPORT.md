# スマートフォン向け操作の追加

## 操作と画面

- 左下の「ビタン！」を1タップで1入力。内部でA/Dを交互に選び、PCと同じjump処理へ渡す。長押しの自動連打や独立した移動スティックはない。
- 右半分のゲーム画面をスワイプして視点操作。既存rotateへ渡すため、TPS/FPSと上下角制限は共通。ボタンの指とカメラの指はpointerIdで独立管理。
- 右下の攻撃ボタンは既存クリックと同じfire処理。手動時は1タップごとに攻撃する。ナイフ自動射出ONではクールダウンを守って照準方向へ発射する。ジャンプブーストは従来どおり接触で自動取得・適用。
- 小ボタンでTPS/FPS、メニュー、全画面を操作。全画面・横画面ロックは対応ブラウザのみ。未対応/拒否でもゲーム状態を失わず、縦画面には案内を出す。
- 水中・死亡・カウントダウン・クールダウン中は該当ボタンを薄く/破線表示。水中の攻撃ボタンは見た目を無効状態にしつつ、タップした際は共通判定を呼ぶ。これによりチュートリアルで「水中は攻撃不可」の理由を実際に体験できる。
- 低い画面でも水分、HP、コンボ、時間、ランキングと操作を配置。ランキングの長い名前にBPが隠れないよう、自分のBPも左下ボタンの上に表示。ホームはタッチでスクロールでき、設定欄や名前入力を禁止しない。
- ノッチ/ホームインジケーター用safe-area、viewport-fit=cover、フォーム16px以上、ゲーム領域だけのtouch-action:none等を設定。PCの画面にはタッチUIを表示しない。ハイブリッドPCは実際のタッチ/マウス入力に応じて切り替える。

## 入力の共通化・保護

mobile-input.jsはA/D交互化と指の役割だけを管理。mobile-controls.jsはDOMと入力変換。BP、コンボ、水分、HP、移動、攻撃頻度等の計算は既存シミュレーション/サーバーのまま。

pointerdownだけを入力受付に使い、touchstart/clickの二重登録はない。同じ指/同じボタンの重複downを無視。指を離す・キャンセル・キャプチャ喪失・ボタン外移動・一時停止・画面遷移・新ラウンド・回転・バックグラウンドで入力を解除する。長押しのintervalや新たな描画ループは作っていない。

カメラのスワイプ開始が包丁攻撃になる既存canvas処理を、タッチの場合だけ除外。PCのマウスクリック/ポインターロックは維持し、タッチモードではロックを要求しない。左側の空き画面をドラッグしても移動も攻撃も発生しない。

CPU/コックやモデル、Vite設定、GitHub Actionsは維持。今回の独立ジャンプ廃止・人間の包丁クールダウン短縮は共通シミュレーションにも反映。死んだふりボタンや専用ジェスチャーは追加せず、既存の自動死んだふり・コック認識・奇襲も維持。ビタンビタンエリアやガスバーナーは追加していない。

## チュートリアル

PC・スマホ共通で独立ジャンプ練習を省いた5段階。表示側はtouchHint/touchTextでタッチ操作の語彙へ変換。タッチ時の案内は「左下のビタンボタン」「1タップで1回」「右側スワイプ」「ジャンプボタン」「攻撃ボタン」「視点ボタン」。PCでは元のA/D・マウス・Vの説明を使う。

5段階をTapInput経由で進める自動テストで、水分15ポイント回復、水中で攻撃不可を試す→外で攻撃、TPS射撃→FPS切替→命中→TPS復帰、最後の8コンボ/100BPを撃破0で完了できることを確認した。実際のTutorialModeの表示とFPS時のモデル非表示も自動テストした。

## オンライン

既存のflop/fire/aimパケットとシーケンス検証を利用。モバイル独自のスコア/位置の確定値を送らない。サーバーは削除済みのjumpパケットを拒否し、PCと同じ0.42秒クールダウン・重複拒否を適用する。ロビー・準備・CPU補充・再戦は既存のタッチ可能なHTMLボタンを使う。

水中の1タップは既存のflopパケットでサーバー側に短い滑り移動を発生させる。従来のキーボード用swim:falseをその直後に繰り返すと、この移動が打ち消されるため、タッチ時だけ不要なidle停止パケットを省く。サーバー側の移動時間/速度を変更せず、新しい移動操作も追加していない。PCモードでは従来のswimパケットを送る。

## 軽量化

画質の初期値「軽量」と保存済み設定を維持。モバイルの描画ピクセル上限は軽量400,000・標準550,000・高画質850,000。PCの従来上限は維持し、既存のpixelRatio/adaptiveScaleと合わせて使う。影やモデルは既存画質設定を使い、形状/当たり判定を変えない。

タッチUIは表示内容の署名が変わるときだけDOMを更新。押下/解放/スワイプだけで描画サイズを変更せず、サイズ更新は端末モード切替や既存resizeイベント時。毎フレームのメッシュ生成や新ライブラリはない。

## 手元での確認

PCの通常ターミナルでBBBフォルダーを開いて実行する。スマホを同じネットワークで使う場合は、PC上のViteをLANに公開して、その表示されたNetwork URLをスマホから開く。

```powershell
Set-Location C:\Users\shota\game-project\BBB
npx.cmd --no-install vite --host 0.0.0.0 --port 5173 --strictPort --configLoader native
```

既に5173で起動中なら重複起動しない。スマホからのlocalhostはPCを指さないため、表示されたPCのNetwork URLを使う。HTTPのLAN試験では全画面/クリップボード等に制約があり得るので、最終的にはHTTPSで確認する。

PCブラウザのエミュレーション試験（5173で起動した状態）：

```powershell
npm.cmd run test:browser -- tests/mobile.browser.js
```

本番オンラインの実機確認は、承認後にHTTPSのフロントとWSSの接続先を揃えて行う。Origin制限を無条件に緩めない。今回はPush・GitHub Pages公開・Render変更/デプロイをしていない。公開URLにはまだ今回の変更が反映されていない。


## スマホ操作カスタマイズ（2026-10-16）

ホームの「スマホ操作設定」、または試合中のメニュー →「スマホ操作設定」から変更する。PCのマウス操作には表示・適用しない。

- 視点感度：0.5〜3.0倍（初期1.0）。タッチの基準係数を0.85から1.3へ引き上げ、初期感度自体を約1.53倍にした。PCのマウス係数は変更していない。
- 「ボタン配置を編集」：ビタン！・攻撃・TPS/FPSをドラッグ。選択中のボタンのサイズを70〜150%で調整する。位置を百分率で表示する。
- 「保存」で適用、「キャンセル」で編集前へ戻す。「初期配置に戻す」は位置とサイズを戻し、保存するまではキャンセル可能。
- 感度は即時保存。配置とサイズは保存ボタンでlocalStorageの `bbb.mobileControls.v1` に記録する。不正な値や読み込み失敗は初期値を利用し、保存できない場合は画面に案内する。
- 位置は画面全体に対する相対座標で保存し、画面回転時はボタンの実寸とセーフエリアに合わせて表示範囲を制限する。編集中はボタン入力・視点入力・ゲーム用キーボード入力を受け付けない。
- チュートリアルはスマホ限定で本文12〜14px、補足11〜12pxへ縮小。説明をスクロール可能にし、操作ボタンとの重なりが小さい位置を選ぶ。進行用ボタンは44px以上を維持する。

今回の検証：フロント239件・サーバー20件の自動テスト成功。本番ビルド・Pages参照検査成功。保存/不正値/画面サイズ別の範囲制限、模擬DOM上の編集・キャンセル・感度反映・誤操作抑止を検証。ブラウザ用テストは計3件（設定テスト1件追加）。実行を試したが、この実行環境ではEdgeが起動直後に終了したためブラウザ検証には到達できなかった。スマホ実機のレイアウト・ノッチ・ドラッグ感・オンライン同時接続は未確認。


## ナイフ自動射出・独立ジャンプ廃止（2026-10-16）

- スマホ操作設定に「ナイフ自動射出」を追加。初期OFFで、同じ保存キーのautoFire真偽値として保存。ONは攻撃ボタンを「AUTO ON」に置き換える。感度・配置・サイズの設定は維持し、過去のjump配置は無視する。
- 既存の描画更新から発射可否を確認し、新しいタイマーや描画ループは作らない。照準方向のfire処理だけを利用し、自動照準や追尾は行わない。
- 水中、死亡・死んだふり中、準備/終了、ポーズ、メニュー・編集、非接続、バックグラウンド/非フォーカス、クールダウン中は停止。サーバーも共通の0.42秒間隔を検証する（以前0.48秒、12.5%短縮）。CPUの0.60秒の基準と攻撃AI間隔は維持。
- チュートリアルでは自動射出ONでも水中の攻撃禁止を試す段階だけ攻撃ボタンを表示する。自動射出は実際に水中で試した後の攻撃段階と最終チャレンジに限定し、進行不能を避ける。
- PCのSpaceを含む独立ジャンプを共通シミュレーション・オンライン入力から廃止。A/Dの跳ね・加速・着地・BP・コンボ・水分消費は維持。ブーストはA/Dの跳ねに引き続き適用する。
- チュートリアルは導入→ビタン→回復→水中/外の攻撃→TPS/FPS→最終チャレンジ。ジャンプ操作なしでクリア可能。内部の既存段階IDを維持し、旧ジャンプ段階だけ飛ばす。
