# ホーム表示崩れ修正（2026-10-17）

## 確認できた原因

- `home.css` に複数世代のホーム配置が残っていた。特に `#characterPanel` の `grid-row:3`（小型横画面では `grid-row:3/6`）が、新しい `.neon-home-main` の子にも適用され、暗黙の行を作っていた。さらに旧タイトルの右余白、プレビュー寸法、モバイル配置も残っていた。
- `neon-home.css` のプレビューは通常フロー内の grid 子で、幅・高さ100%と intrinsic canvas 寸法が競合できる構造だった。枠の overflow も制限されていなかった。メイン領域は縮小不可・最低440px指定だった。
- `seafood-menu.js` は縦横比1のカメラで256/384pxの正方形を描き、CSSで可変の長方形へ引き伸ばしていた。カメラ距離は最大辺×1.7であり、表示枠や視線方向を考慮していなかった。
- `battle-view.js` の `updateChefMeters()` はステージ種類のみ判定していた。ホーム上で準備中の厨房シミュレーションにも「？ 0%」を表示する経路があった。読み込み表示ではなくコックの疑問度である。

以上はコードから確認した原因。スクリーンショットがこの依頼には届いておらず、実画面との照合は未完了。

## 修正

- 旧ホームのレイアウト指定を `:not(.neon-home)` 内に隔離。共通のガチャ・装備・ダイアログのスタイルは保持。NEONホームの配置は `neon-home.css` を所有元とする。
- キャラクター枠に layout/paint containment と overflow:hidden を設定。canvas は枠に絶対配置し、名前・称号・切り替え・下部メニューへ侵入できない構造にした。
- デスクトップの可変中央領域と短い画面向け余白を調整。PCは左右2列、狭い縦画面は1列。小型画面の通常スクロールは保持。
- Box3の8頂点を視線方向の座標で評価し、FOV・アスペクト比・姿勢変化用余白からカメラ距離を計算。読み込み・種類変更・サイズ変更時に反映。プレビュー以外のモデルサイズや当たり判定は変更しない。
- 表示枠に合う縦横比で描画。低画質は長辺512px・DPR最大1、通常は長辺768px・DPR最大1.5に制限。プレビュー用既存レンダラーの生成時にアンチエイリアスを有効化。リサイズはバッファ寸法が変わった場合のみ。8/12Hzの更新上限、単一の既存描画ループを維持。
- コックのメーターはホーム／結果では非表示。プレイ・カウントダウン・ポーズ中のみ既存表示判定を使用。コックAIは変更しない。

## 検証

- フロントエンド367件（正本・親の開発用コピーとも）、サーバー54件の自動テストに全件成功。
- 追加：画面縦横比0.35〜2.8、3種類のモデル寸法、3つの向きで全8頂点がカメラ内に収まること。動き抑制設定中のリサイズ、GPUバッファ上限、モデル再生成なし、メーターの表示状態。
- GitHub Pages向けビルドと相対アセット検査は成功。既存の大きなJSチャンクの警告は残る。
- 1920×1080、1536×864、1366×768、1440×900、1024×768、スマホ縦横のブラウザ検査を用意。ただしこの環境ではEdgeがページ表示前に終了（crashpad TransactNamedPipe / Target closed）。内蔵ブラウザもローカルURLへの接続がタイムアウトした。そのため実画面のレイアウト、魚・イカの輪郭、PC／スマホの操作、オンライン実機は未確認。
- セーブ、ゲームバランス、オンライン通信、サーバーコードは変更なし。push／デプロイなし。
