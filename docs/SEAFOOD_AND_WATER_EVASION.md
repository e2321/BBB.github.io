# 海鮮キャラクター・モデル画質・CPU水たまり回避

## 操作

ホーム右側の4枚の実モデル画像から魚・エビ・イカ・タコを選ぶ。パネル下部の「モデル画質」は軽量・標準・高画質。種類と画質を別々にlocalStorageへ保存する。初期値は魚・標準。

オフラインBBBの操作キャラクターに選択を適用。CPUは4種類から割り当てる。オンラインはルーム参加時の種類をサーバーが検証し、メンバーと各魚の状態に保持する。再接続・再戦でも維持。ロビーのCPU補充、準備、再戦、ホスト移行の条件は変更していない。画質は送信しないため、各PCで独立する。

チュートリアルでは既存の魚の生成・操作・アニメーションをそのまま使う。

## 実装

- `battle-ai.js` / `battle-simulation.js`: 水中被弾で回復より脱出を優先。攻撃元と障害物に応じた経路を選ぶ。最大6秒で回避状態を解除し、被弾した水たまりは少なくとも脱出後4秒間目標から除外し、再進入する経路も避ける。攻撃元不明にも対応。移動・加速・攻撃の定数は変更していない。
- `seafood-model.js`: 共通の生成処理でエビの節・尾扇・触角・脚、イカの外套膜・側ひれ・10本の腕、タコの頭・8本の腕・吸盤を構成する。材質は落ち着いた皮膚色。個体ごとの識別色・水分・虹色・被弾表示を適用。節・尾・腕に別々の動きを付ける。
- `seafood-settings.js`: 種類の検証、画質パラメータ、保存、ゲーム乱数を消費しないCPUの種類割り当て。
- `fish-quality.js` / `fish-model.js`: 既存GLBのデザイン・骨格を再利用。軽量時だけ近接頂点を統合し、法線マップ・コート・影を減らす。標準・高画質の魚の表面形状は元のまま。チュートリアルの呼び出しには画質補正を適用しない。
- `battle-view.js`: 種類・PC側の画質から描画モデルを選び、変更時は旧モデルの専用材質を破棄する。共有ジオメトリをキャッシュし、毎フレームのメッシュ生成は行わない。物理・当たり判定は既存ロジックのまま。
- `seafood-menu.js` / `game.js` / `index.html` / `style.css`: ホームの4カード、保存した選択、画質設定、狭い画面での折り返し。画像は実際の3Dモデルをオフスクリーン描画して生成する。
- `online-client.js` / `server/src/session.js` / `server/src/room.js`: 入室時に種類だけを送信し、サーバー検証後に保持・同期する。既存の試合状態遷移は変更していない。
- `tests/seafood.test.js` / `tests/fish-quality.test.js` / `tests/seafood.browser.js` / `server/tests/characters.test.js`: 回避・画質差・材質分離・保存・モデルによるゲーム性能差がないこと・種類の保持を検証。

## 実際の品質差

新モデルは同じ生成関数にquality=low/medium/highを渡す。分割数、曲線の細かさ、影・膜の材質、アニメーション更新を変更する。アニメーション更新の上限は20/40/60Hz。位置は毎フレーム追従する。

魚の三角形数は軽量88,910、標準/高画質128,138で、軽量は約31%減。エビの頂点数は6,018 / 25,338 / 86,202、イカは2,886 / 12,126 / 42,558、タコは10,080 / 44,880 / 153,360。ゲームの当たり判定・速度・HP・BP・ジャンプ・水分の定数は共通。

## 検証結果（2026-10-15）

- フロント・ゲームロジックの自動テスト138件成功。
- サーバーの自動テスト20件成功。種類の検証・再接続・再戦時の維持、CPU補充OFFも検証。既存のロビー・再戦ユニットテストも成功。
- Vite本番ビルドとPages出力チェック成功。ただし通常コマンドは既存ファイルのrealpathでEPERMとなる環境制限が続いているため、検証時だけresolve.preserveSymlinks=trueを指定してビルドした。リポジトリのVite設定、Pages workflow、Render設定は変更していない。既存のチャンクサイズ警告あり。
- ブラウザーはEdgeが起動時に終了してしまい、画面確認まで到達できなかった。レイアウト、サムネイルの実画面、自然さ、実測FPSは未確認。専用ブラウザーテストは追加済み。
- 実通信の統合テストは、ローカルサーバーのhealth疎通待ちで失敗した。実際の複数ブラウザーによる同期・再戦、本番WSSは未確認。

GitへのPush・外部デプロイは実施していない。公開反映にはフロントとオンラインサーバーの両方の更新が必要。
