# 捌かれるな！！ — 脱出＆エンドレスサバイバル

オリジナル制作の魚になり、業務用厨房で必死に跳ねて生き延びるThree.jsゲームです。第三回改良前のコード・モデル・テストは `backups/v2-before-modes/` に保存しています。元の `game_spec.md` を残し、今回の追加指示を優先しています。

## 起動

Node.js 20.19以上、または22.12以上が必要です。

```powershell
npm.cmd install
npm.cmd run dev
```

http://127.0.0.1:5173/ を開き、魚・料理人の読み込み完了後、モードを選びSTARTを押してください。PowerShellでは `npm.cmd` を使います。制作済みGLBを同梱しているため、遊ぶだけならBlenderは不要です。依存取得後、実行時の外部アセット接続はありません。

```powershell
npm.cmd run build
npm.cmd run preview
```

配布用プレビューは通常 http://127.0.0.1:4173/ 。`dist/` を静的ホスティングへ配置できます。HTMLを `file://` で直接開かず、HTTPサーバーを使用してください。

## 操作

| 操作 | 効果 |
| --- | --- |
| A / D | 尾を打ち、カメラの水平前方へ跳ねる。左右移動ではありません |
| A / Dを交互に0.16～0.40秒間隔 | 体を左右へ曲げ、推進力が増加。約0.28秒が最も強い |
| 空中でもう一度A / D | 2段ジャンプ。3段目は不可 |
| マウス移動 / 画面ドラッグ | 進む方向とカメラを変える |
| Esc | マウス固定を解除 |
| ホイール | ズーム2.2～4.8m |
| タッチ端末のA / Dボタン | キーボードと同じ跳ねる操作 |
| 入力を止める | 接地し、低速状態が0.8秒続くと死んだふり |

キーの押しっぱなし・リピート・Spaceではジャンプしません。魚は横倒しで、入力と同期して口を大きく開き、頭と尾を近づけて伸ばします。着地後の反動と尾の遅れ、空中の姿勢変化、水しぶきがあります。死んだふり中は口と胴体を静止します。

## 脱出モード

まな板の上で、別の料理人が包丁を振り下ろそうとする場面から開始します。この料理人は固定位置にいて追跡せず、導入演出に当たり判定はありません。最初からA / Dを受け付け、入力した時点で通常の追従カメラに戻ります。入力しなければ1.8秒で導入カメラが終わります。

全長約43m、前版の約2倍のルートです。前半と後半の調理台・食器・コンロ・料理人エリアを突破し、最後のシンク底の排水溝でのみクリアします。食器8個には横ずれと段差があり、最大段差0.15mを通常の2段ジャンプで越えられます。

追跡する料理人は前後のエリアに各1人。ワゴンと高い柵が進路を塞ぎ、死んだふりによる奇襲でワゴンが移動します。疑い度が下がると警戒→接近→拾い上げに変化。**「今だ！」と表示されたらA / D**。拾い上げ開始0.10～1.20秒の約1.1秒が成功範囲で、成功すると3秒気絶します。少し早い・遅い入力も普通に跳ねて逃げられ、入力失敗そのものを即死にはしません。手を伸ばしたまま放置すると1.75秒で捕獲されます。投げられた包丁は気絶中も飛び続けます。

5か所のチェックポイント：前半食器後、前半コンロ後、前半料理人後、後半食器後、後半コンロ後。接地して通過すると保存し、RETRYで水分100・速度0から再開します。突破済みワゴンは開いた状態を保存。脱出の経過時間と挑戦回数は継続します。「最初からやり直す」とタイトルからのSTARTは新しい挑戦です。

## サバイバルモード

9つの調理台を12本の橋でつないだ専用厨房です。水場は9か所。料理人も台と橋の経路を歩いて追跡します。

- 開始時1人、30秒ごとに1人追加、210秒で最大8人。
- 増援はプレイヤーから3.2m以上離れ、他の料理人や炎と重ならない場所を選びます。出現後2.5秒は様子見、投擲開始まで6秒の猶予があります。
- クリア条件はなく、ゲームオーバーまで生存時間を計測。RETRYは0秒・料理人1人から。
- 生存時間順のTOP 10をlocalStorageに保存。タイトルの「サバイバル記録 TOP 10」で確認できます。
- 保存不可の環境でもゲームは続行し、そのページ内の記録は保持します。記録処理は `records.js` のRepositoryに分離しています。オンライン送信は未実装です。

魚の操作・水分・死んだふり・疑い度・料理人AI・死亡演出は両モードで共有しています。

## 水分・炎・ゲームオーバー

通常の水分減少は毎秒1.5、ジャンプごとに0.25。水場へ接地すると毎秒15回復します。コンロの橙色の高温範囲はさらに毎秒6減少し、離れると通常速度に戻ります。赤い輪は直接炎の危険範囲で、点火中に触れると即死。炎と高温は独立した当たり判定です。バーナーごとに周期と点火順が異なり、消えるタイミングや空いた側を選べます。

| 原因 | 表示・演出 |
| --- | --- |
| 直接捕獲 / 拾い上げ | 捕まりました。料理人の手元に魚を持ち上げる |
| 包丁 | 刺身になりました。存在・読み込みを確認した刺身画像を表示 |
| 炎 | 焼き魚になりました。提供された焼き魚画像を中央表示 |
| 水分0 | 干からびました。魚が褐色化し、濡れた光沢を失って動かなくなる |
| 落下 | 台から落ちました。着地の操作説明を表示 |

すべてのゲームオーバー画面にRETRYとタイトルへ戻るボタンがあります。料理写真は `object-fit:contain` で比率を維持します。提供画像の実際の名前は **`assets/images/grilled_fish.png.jpg`** でJPEGでした。元画像を変更せず、この実在ファイルを読み込んでいます。刺身画像は前回制作分を `assets/images/sashimi.png` に配置しました。`image-assets.js` は存在するファイルだけをビルドに含め、刺身画像が未配置・読み込み失敗でも正常にゲームオーバーできます。

## モデル・厨房

Blender 5.2.2 LTSのPython APIで魚と料理人をオリジナル制作。完成済み外部モデルは使用していません。

- 魚：45.5cm（従来35cmの1.3倍）、65,299頂点・128,138三角形、7ボーン、7アニメーション。独立した顎、滑らかな胴体、口腔、エラ、目、各ヒレ、鱗を造形。4096×2048の体色・法線・粗さマップ、銀色～淡いピンク、濡れたclearcoat。GLB約44.4MB。
- 料理人：17ボーン、36,547頂点・72,276三角形。鼻・頬・眉・目・口・耳、コック帽、調理服、エプロン、ボタン、縫い目、指、靴を制作。Idle / Walk / Windup / Throw / Inspect / Stunned / Capture / IntroChopの8クリップ。GLB約2.7MB。
- 厨房：傷のあるステンレス、包丁傷のあるまな板、陶器の皿・ボウル、金属の鍋、五徳とバーナー、立体的な炎と暖色光、深いシンクと金属排水溝、水面、床・壁タイル、業務用天井照明。
- 描画：PBR、PMREM環境反射、ACESトーンマッピング、影。HIGH / MEDIUM / LOWは画面解像度と影を調整し、モデルのポリゴンやテクスチャ解像度は変更しません。

魚の接触球は半径0.0845mへ1.3倍に調整。基本ジャンプ速度2.6m/s、2段目2.3m/s、推進0.65m/s、水平速度上限3.2m/sは維持しています。足場を拡幅し、カメラ距離も調整しました。

## Blenderで再生成

```powershell
npm.cmd run model:build
```

魚・料理人を両方生成します。個別には `npm.cmd run model:fish` / `npm.cmd run model:chef`。

Windowsでは `C:/Program Files/Blender Foundation/` を検出。別の場所なら：

```powershell
$env:BLENDER_PATH = 'D:\Apps\Blender\blender.exe'
npm.cmd run model:build
```

または直接実行できます。

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --factory-startup --python tools/build_fish.py
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --factory-startup --python tools/build_chef.py
```

GLBに加え、編集可能な `.blend`、生成テクスチャ、制作情報、プレビューを `assets/fish-source/` と `assets/chef-source/` に保存します。Blenderを起動できない場合は実行ファイルを `BLENDER_PATH` に指定してください。ゲーム実行中のモデル読み込みエラーはSTARTを無効にして具体的なエラーを表示します。

## 検証

```powershell
npm.cmd test
npm.cmd run test:browser
npm.cmd run build
```

ブラウザテストは別ターミナルで開発サーバーを起動してください。Microsoft Edgeをヘッドレス、ソフトウェアWebGLで使用します。

27件のロジック・アセットテストで、物理・2段ジャンプ・全区間・5チェックポイント・2ゲート・奇襲窓・各死亡原因・炎/高温の分離・安全な増援・8人上限・9台間のAI経路・TOP 10・保存不可・GLBの骨格とPBRを検証します。

全ルートテストは初期位置から位置・速度を注入せず、AIを停止せず、実際のA/D入力で食器8個に着地し、2回の奇襲、5チェックポイント、最後の排水溝まで約78.6秒でクリアしました。これは経路を知る自動操縦の時間です。

ブラウザ検証では、モデルと顎の動き、死んだふりの静止、導入、入力、カメラ、実操作による全ルート、各死亡と写真、Retry、モード選択、8人描画、記録・ランキング、モバイル入力、保存不可、刺身画像読み込み失敗を確認します。個別の死亡・増援時刻の検査は開発用状態注入を使用し、210秒間の自然プレイを代替するものではありません。検査フック `window.__game` は開発版のみです。画像は `tests/screenshots/v3-*.png` に保存します。

## 残る制約・未確認事項

- モデルはオリジナルのプロシージャル造形で、実物の写真スキャンではありません。
- 品質を優先した魚GLBは約44.4MB。初回ロードとGPUメモリ使用量が大きく、ソフトウェアWebGLでは描画が遅くなります。実GPUのFPSとスマートフォン実機の性能は未測定です。
- 初見の攻略時間・長時間サバイバルの難易度は実ユーザーによる測定が未実施です。自動経路のクリア確認と個々のAI・増援テストを行っています。
- 魚の衝突は操作感を保つ球近似、食器などの衝突はAABB近似です。
- 記録はこのブラウザ内の保存です。オンラインランキング、マルチプレイ、料理人のプレイヤー操作は今回の対象外です。
