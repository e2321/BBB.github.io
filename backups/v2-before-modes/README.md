# 捌かれるな！！ — 厨房アスレチック・チュートリアル

35cmの魚になり、食材、食器の足場、周期的な炎、料理人、最後のシンクを突破する3Dゲームです。A/Dの尾打ち、2段ジャンプ、死んだふり、拾い上げの瞬間の奇襲を使い、排水溝へ逃げます。

今回の拡張前のコード・アセット・テストは `backups/v1-before-expansion/` に保存しています。元の `game_spec.md` は変更していません。今回のユーザー指示に従い、ステージ座標と進行を拡張しました。

## 起動

Node.js 20.19以上、または22.12以上。開発・検証環境はWindows / Node.js 24.21.0 / Microsoft Edgeです。

```powershell
npm.cmd install
npm.cmd run dev
```

**http://127.0.0.1:5173/** をブラウザで開きます。魚のGLBとPBRテクスチャの読み込みが完了するとSTARTが有効になります。PowerShellのスクリプト実行制限を避けるため上記では `npm.cmd` を使っています。通常の環境では `npm install`、`npm run dev` でも起動できます。

制作済みのGLBと画像を同梱しているため、遊ぶだけならBlenderは不要です。依存パッケージ取得後は、ゲームの実行時に外部アセットサイトへ接続しません。

```powershell
npm.cmd run build
npm.cmd run preview
```

`dist/` の中身を静的ホスティングへ配置できます。プレビューは通常 http://127.0.0.1:4173/ 。サブディレクトリ配置に対応します。`file://` で直接開く構成ではありません。

## 操作

| 操作 | 効果 |
| --- | --- |
| A / D押下 | 尾を打ち、カメラの水平前方へ跳ねる。左右移動ではない |
| AとDを交互に約0.28秒間隔 | 推進ボーナス。0.16～0.40秒で有効 |
| 空中でもう一度A / D | 2段目ジャンプ。3段目ジャンプは不可 |
| マウス移動 | Pointer Lock中のカメラ回転 |
| Esc | Pointer Lockを解除し、ドラッグ操作へ |
| マウス・タッチで画面をドラッグ | カメラ回転。20～75度の俯角 |
| ホイール | カメラ距離2.0～4.5m。壁・縁での自動調整あり |
| タッチ端末のA/Dボタン | キーボードと同じ尾打ち |
| 入力を止める | 接地・低速状態が0.8秒続くと死んだふり |

押しっぱなし、キーリピート、Spaceはジャンプとして扱いません。同じキーを押し直しても弱く進めます。左右へ曲がるにはカメラを回してからA/Dを押します。

## 5つの区間

1. **まな板**：食材と調理器具を避けて先へ。道中の水たまりで水分を補給できます。
2. **食器**：4つの皿・ボウルの足場を、左右のずれと高低差を見ながら渡ります。空中での2段目入力を使います。
3. **コンロ**：3つのバーナーが位相をずらして点火。周期4.4秒、点火時間1.65秒。炎に触れると通常の乾燥に加えて水分が毎秒18減ります。炎が消えるのを待つか、空いた側を通ります。
4. **料理人**：料理人が押さえるワゴンが出口を塞ぎます。入力を止め、疑い度を下げると近づいて拾おうとします。**「今だ！」の合図でA/Dを押す**と奇襲成功。料理人は2秒スタンし、ワゴンが脇に動いて通路が開きます。普通の2段ジャンプでワゴンや横の高い柵を越えることはできません。
5. **シンク**：最後の隙間と段差を跳び越え、中空のシンクへ。底に降り、光る排水溝へ入るとクリアします。

料理人区間に入ると最初の3秒はWAITING、最初の包丁投げは入場6秒後。操作を覚えた直後に止まって死んだふりを試せる猶予を設けています。その後の追跡、0.6秒の包丁予告、3秒間隔の投擲、疑い度による警戒・接近・拾い上げは維持しています。既存の包丁は死んだふりやスタン中も飛び続けます。

## 水分とチェックポイント

通常は水分が毎秒1.5、ジャンプ1回で0.25減ります。水たまりの上に接地した高さで毎秒15回復。水分0でゲームオーバー。水分に応じた接地摩擦も維持しています。

- CHECKPOINT 1：食器エリアの出口。水分回復地点。
- CHECKPOINT 2：料理人エリアの手前。水分回復地点。

接地してチェックポイントに入ると自動保存します。死亡後の **RETRYは最後のチェックポイントから再開**。位置・速度・ジャンプ・疑い度・料理人・包丁・水滴・水分・死亡演出をリセットし、水分100で再開します。CP2からの再開では料理人への奇襲をもう一度行います。「最初からやり直す」でチェックポイントを消して新しい挑戦を開始できます。

クリア時間は1つの挑戦全体の累積プレイ時間で、結果画面の待ち時間は含めません。チェックポイント再開では時間を引き継ぎ、挑戦回数が増えます。クリアスコアは `5000 + max(0,300-累積秒数)*30 + 残水分*10 + 奇襲回数*500 + 交互入力回数*20 - (挑戦回数-1)*250`。最高スコア・最短時間は拡張版専用のlocalStorageキーに保存します。保存不可でもゲームは続行します。

## 原因別ゲームオーバー

| 死亡原因 | 画面と演出 |
| --- | --- |
| 直接捕獲・拾い上げ | **捕まりました**。料理人が魚を手元へ持ち上げ、カメラがその姿を映す |
| 投げた包丁 | **刺身になりました**。中央に保存済みの料理写真風の刺身画像を表示 |
| 水分ゼロ | **干からびました**。魚へカメラが寄り、同じモデルが褐色になり、光沢を失い、脱力する |
| 足場から落下 | **台から落ちました**。着地と2段ジャンプのヒントを表示 |

すべての結果画面にRETRYを表示します。死亡の判定は文字列の推測ではなく `CAPTURE / KNIFE / DRY / FALL` の原因コードで行います。共通データは `death-presentation.js` に分離し、魚の演出は `fish-model.js` に置いています。将来のモードでもこの原因コードと演出データを再利用できます。

刺身画像は `public/assets/images/sashimi.png` に実ファイルとして保存済み。読み込み確認後に表示し、読み込みに失敗した場合は壊れた画像を表示せず、必要なファイル名を案内します。制作方法と最終プロンプトは `assets/sashimi-prompt.md` に記録しています。過度にグロテスクな描写はありません。

## Blenderで魚を再制作

Blender 5.2.2 LTSのPython APIで自動制作しました。再生成：

```powershell
npm.cmd run model:build
```

Windowsでは `C:/Program Files/Blender Foundation/` のBlenderを検出します。別の場所にある場合は `BLENDER_PATH` を指定：

```powershell
$env:BLENDER_PATH = 'D:\Apps\Blender\blender.exe'
npm.cmd run model:build
```

直接実行する方法：

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --factory-startup --python tools/build_fish.py
```

Blenderがない環境で再制作する場合は [公式サイト](https://www.blender.org/download/)からインストールして実行ファイルのパスを指定してください。スクリプトは低品質な代替モデルへ切り替えません。ゲームのGLB読み込みが失敗した場合も、STARTを有効にせず具体的なエラーを表示します。

- 180断面×112周方向の滑らかな胴体。全長約35cm。
- 頭部・口・エラ・左右の目・鼻孔・背びれ・胸びれ・腹びれ・尻びれ・二叉尾とヒレの筋。
- 約12.8万三角形。4096×2048の体色・法線・粗さマップをGLBへ埋め込み。
- 6ボーンの滑らかなウェイト。左右の尾打ち・空中・死んだふり・着地・捕獲・乾燥の7アニメーション。
- 原寸のGLBをGLTFLoaderで読み込み、AnimationMixerで再生。基本姿勢は横倒し。
- 当たり判定は従来の半径0.065mの球。基本ジャンプ2.6m/s、2段目2.3m/s、推進0.65m/s、最大水平速度3.2m/sを維持。

モデルと編集可能なBlenderファイルの詳細は `assets/fish-source/README.md`。実際の生成情報は `assets/fish-source/metadata.json`。

## 到達性と検証

```powershell
npm.cmd test
npm.cmd run test:browser
npm.cmd run build
```

ブラウザテスト時は別ターミナルで `npm.cmd run dev` を起動してください。既定ではインストール済みMicrosoft Edgeをヘッドレスで使用します。別のブラウザを使う場合は `playwright.config.js` の `channel` を変更してください。

実施した検証：

- **ロジック・アセットテスト21件成功**。入力・2段ジャンプ・摩擦・衝突・疑い度・奇襲・ゲート・炎・水分・チェックポイント・死亡原因・包丁スイープ・死亡優先を検査。GLB内の骨格、ウェイト、7クリップ、埋め込みPBR、全長、4Kテクスチャと刺身画像の実在も検査。
- **Edge / Playwrightテスト5件成功**。GLBロード、START、A/D、Space無効、リピート無効、カメラ・リサイズ・LOW、全ルートのクリア、2つのチェックポイント復帰、捕獲・刺身・乾燥・Retry、タッチ端末エミュレーション、localStorage保存不可を検査。未処理のページ例外なし。
- **全ルートの実物理到達テスト**。初期位置から位置・速度を注入せず、AIを止めずに、通常のA/D入力で4つの食器足場に着地し、2つのチェックポイント、奇襲成功、最後の段差、排水溝を通過。自動操縦は約42秒でクリア。
- **ビルド成功**。GLB・刺身画像・ライセンス表示を `dist/` に出力。
- **配布用プレビュー成功**。制作済みGLBの読み込み完了とSTART後のHUDを確認。ページ例外・HTTPエラーなし、`window.__game` が配布版に存在しないことを確認。
- `tests/screenshots/v2-*.png` にタイトル、魚のジャンプ、LOW、クリア、捕獲、乾燥、刺身、コンロ、タッチの画像を保存し、見た目を確認。

1段目の理論上昇量は `2.6²/(2×9.8)=約0.345m`。食器の段差は最大0.15m、最終シンクの段差は0.20mで、隙間と横ずれは2段ジャンプと推進で到達できます。閉じたワゴンは高さ1.2m、横の柵は高さ1.0mで、普通のジャンプでは越えられません。

ブラウザでの原因別演出やチェックポイント個別テストには開発用の状態注入を使用します。ステージ到達テストは実際の操作・物理・AIで行います。検査フック `window.__game` は開発時のみで、配布ビルドから除去されます。

## 残る制約・未確認の点

- 魚は新規制作したマダイ参考モデルで、実魚の写真スキャンではありません。料理人は既存の関節式モデルを維持しています。
- 魚GLBは品質を優先し約44.1MB。初回読み込みと4KテクスチャのGPUメモリ使用は大きめです。LOWでもモデルの品質は下げません。
- **初見3～5分を目標**に、各区間の説明と再挑戦を設計していますが、初見ユーザーによる実測は未実施です。経路とタイミングを知る自動操縦は約42秒でクリアし、待ち時間でプレイ時間を強制的に引き延ばしてはいません。
- ヘッドレス検証はソフトウェアWebGL。実GPUでのFPS測定とスマートフォン実機の確認は未実施です。タッチ入力はブラウザのモバイルエミュレーションで確認しています。
- 皿・ボウルの足場は食器とトレーの上面をAABBで近似しています。魚の外形全体の精密な接触判定ではなく、操作感を維持する球近似です。

エンドレスモード、料理人の増加、オンラインランキング、マルチプレイ、料理人のプレイヤー操作は今回実装していません。

アセットの制作元・ライセンスと参照APIは [ASSETS.md](ASSETS.md)、刺身画像の最終生成プロンプトは [assets/sashimi-prompt.md](assets/sashimi-prompt.md) を参照してください。
